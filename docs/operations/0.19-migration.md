# Migrating to 0.19.0-rc.1

This is a release candidate. Keep the existing stable installation until the validation matrix meets your deployment needs. No production network changes are part of this upgrade work. New write workflows still require disposable-controller and adopted-hardware tests before stable promotion.

## Priority and behavior changes

1. **Reliable reads:** concurrent requests reserve distinct dispatch slots; authentication is shared across callers. Transient failures retry only reads, with bounded backoff and `Retry-After`. Explicit authentication rejection permits one refreshed-token replay unless a workflow disables retries. Pagination detects repeated pages, changing totals, malformed envelopes and size limits, and fails rather than silently claiming complete inventory. Client lookup normalizes MAC/IP/name/hostname and rejects ambiguous matches among online clients.
2. **Predictable writes:** omission of `dryRun` means preview. Existing automation must send `dryRun: false` deliberately. Payload validation applies to previews too. There is no universal network-safe apply: radio, SSID, port, PoE, reboot and restore actions can disrupt connectivity.
3. **Verified controls:** AP/gateway configuration, typed AP radios, SSID basic settings and guarded switch ports use bounded readback. An accepted API request is not proof of changed device behavior.
4. **Smaller discovery:** deprecated aliases are hidden by default. Compact mode exposes four discovery/dispatch tools instead of all enabled operation schemas at initialization. Permissions still apply to every operation.
5. **Diagnostics and maintenance:** Wi-Fi/log/camera composition reports missing evidence, private CA bundles preserve TLS validation, and shared redaction masks credential fields in logs and structured tool responses.

## Mutation result contract

| Status | Meaning |
| --- | --- |
| `planned` | Preview only; no mutation request was sent |
| `submitted` | Request accepted; no semantic verification is available for this legacy operation |
| `verified` | Requested readable fields matched, or already matched and no write was needed; inspect `changed` / verification details |
| `mismatch` | Readback still differed after bounded attempts |
| `unknown` | Outcome cannot be established, including failed readback or an uncertain write |
| `unverifiable` | Requested state cannot be compared reliably using the documented read surface |
| `partial` | Targets completed differently; inspect each target before retrying |

Never blindly repeat an uncertain mutation. Read current state first. Multi-port profile assignment is sequential and stops after an uncertain write; no rollback is attempted. Verification confirms controller-observed configuration, not physical connectivity or every device's eventual provisioning state.

## Exposure settings

```dotenv
OMADA_CAPABILITY_PROFILE=safe-read
OMADA_CATALOG_MODE=standard
OMADA_INCLUDE_DEPRECATED=false
OMADA_ALLOW_TOOL_HEADERS=false
OMADA_STRICT_SSL=true
# OMADA_CA_FILE=/absolute/path/to/private-ca.pem
```

Use `OMADA_CATALOG_MODE=compact` for `searchOperations`, `describeOperation`, `getServerCapabilities` and `callOperation`. Discover an operation, inspect its exact schema, then call its exact name with `arguments`. Dispatch cannot accept raw API URLs or HTTP methods. A write-capable dispatcher is marked destructive; hosts approving whole tools may prefer standard mode for granular approvals.

`OMADA_TOOL_CATEGORIES` replaces profile defaults. Select only the categories you intend to use, for example `devices-ap:rw,wireless-ssid:rw,devices-switch:rw` for new write previews. Add `wireless-radio:r,logs:r,client-insights:r` for the composed diagnostics. `admin` / `all:rw` exclude restore operations. Recovery requires explicit `recovery:rw`, `dryRun: false`, and `confirmDangerous: true`; the boolean is not a human approval mechanism.

`OMADA_INCLUDE_DEPRECATED=true` restores legacy aliases. `compatibility` remains a deprecated alias for `admin`, not a private-controller API implementation. The unused duplicate `getDevicesStats.ts` was removed; the registered `listDevicesStats` tool remains.

If `OMADA_ALLOW_TOOL_HEADERS=true`, only `X-Request-ID` and `X-Correlation-ID` are accepted, with at most 128 printable ASCII characters. Authentication/host headers are not tool arguments. `OMADA_CA_FILE` supplies a PEM CA bundle to Node's TLS agent; keep strict SSL enabled and mount the file read-only in Docker. Redirects are disabled to avoid forwarding controller credentials.

## New workflow limits

- **AP radio:** channel and width must be advertised by the selected AP. Unsupported bands and missing capability data fail before a write. Custom dBm and automatic channel selection are not exposed. Sibling bands are preserved, with an additional pre-write consistency read; the API has no atomic compare-and-set.
- **SSID:** changes are limited to name, broadcast visibility, guest status and Wi-Fi sharing policy. Required security settings are preserved internally. Hiding the SSID name is not disabling the SSID. No password-management surface is added.
- **Switch ports:** 1–32 unique explicit port IDs; all are checked before sending a mutation. Known LAG changes require `allowDisruption`. PoE changes require a confirmed profile override on every changed port; enable and verify it separately first. Uplink/trunk/stack membership is not documented by this detail response and remains unknown; the guard does not prove disruption-free changes. PoE/status/profile changes can disconnect clients. Multi-port outcomes and readback limits are explicit.
- **Wi-Fi health:** percentages are controller reports; thresholds are review heuristics, not universal health scores. No RF scan or automatic retuning occurs.
- **Log diagnosis:** first pages only, with timestamp/query completeness. Empty data does not prove logging is disabled or that no incidents occurred.
- **Camera connectivity:** client and session evidence only. Attachment/VLAN/PoE/RTSP investigation may need further tools. It cannot assess Frigate model recognition.

See [support matrix](../support-matrix.md), [release validation](0.19-validation.md), and [security policy](../../SECURITY.md) before promotion. Zod's remaining high-severity dependency advisory is an unresolved release-candidate limitation, not a completed fix.

## Legacy contract limits

Direct event/alert list calls still accept omitted time bounds for compatibility even though the tag spec requires them; supply both bounds. `diagnoseLogs` always supplies both. Audit calls without bounds use the documented controller default; partial audit windows are rejected. The legacy `getTopThreats` signature still differs from the individual security spec and is not newly validated by this candidate.

Configuration drift storage, RF history, certificate pinning, and broad configuration-review workflows remain follow-on projects. This release establishes trustworthy reads, explicit previews and bounded verification first.
